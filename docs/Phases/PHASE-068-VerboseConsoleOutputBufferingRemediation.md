FILES:

ACCEPTANCE CRITERIA:
- Verbose ([verbose] ...) output is flushed to the console as it is produced during a run, not batched until process exit, when invoked via the packaged embedded-runtime launcher.
- Fix applies at the packaged entry-point/launcher level (e.g. unbuffered stdout mode) rather than adding flush=True to individual print() call sites throughout app/cli.py and app/orchestrator.py.
- Regression/manual verification: running the packaged build with --verbose against a dry-run or mocked collection shows incremental output before completion, not all at once.
- No change to what is logged or the log_verbose() call sites/content.

CONSTRAINTS:
- Change confined to the packaged launcher entry point and/or its invocation (run_portable.py, Start_NetworkRecon.cmd/.ps1 as generated by build_portable.py).
- No changes to app/cli.py, app/orchestrator.py log_verbose() logic or call sites.
- No changes to CLI arguments or verbose message content.

KNOWN RISKS:
- Unbuffered stdout mode can marginally reduce I/O throughput; negligible for this tool's console-output volume.

OUTSTANDING RISKS:
- Root cause (stdout buffering under a redirected/piped console in the embedded launcher) is a strong evidence-based hypothesis from code inspection (no -u flag, no PYTHONUNBUFFERED, no explicit flush); confirm with a live timed run before closing.
